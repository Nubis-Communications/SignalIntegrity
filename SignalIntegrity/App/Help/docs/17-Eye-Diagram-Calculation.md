# Eye Diagram Calculation {#sec:Eye-Diagram-Calculation}

When a [Simulation](08-Simulation.md#sec:Simulation) or [Virtual Probing](10-Virtual-Probing.md#sec:Virtual-Probing) project is created and the schematic contains a [Eye Probe](23-Built-in-Devices-Parts.md#device:Eye-Probe) or a [Differential Eye Probe](23-Built-in-Devices-Parts.md#device:Differential-Eye-Probe) element, when the simulation is run, for each one, an eye diagram is created using the waveform produced in conjunction with the baud rate specified and the [Eye Diagram Properties Dialog](21-Eye-Diagram-Properties-Dialog.md#sec:Eye-Diagram-Properties-Dialog) specified.

This section explains how the eye diagram is created and will refer to various [Eye Diagram Properties Dialog](21-Eye-Diagram-Properties-Dialog.md#sec:Eye-Diagram-Properties-Dialog) during the explanation.

The reciprocal of the baud rate specifies the unit interval, or the length of one UI in the waveform. The goal of the eye diagram is to show, overlapped, all of the portions of the waveform that pass through the unit interval. So, for a given time in a waveform $t_{k}$, and a given UI length, $UI$, the time of each point in the waveform, $t_{eye}$ inside the unit interval is given by: $$t_{eye}=\left(t_{k}+\frac{UI}{2}\right)\:\%\:UI$$ where $\%$ represents the modulo operator. You can see by this definition that $0\le t_{eye}\le UI$ and that when $t_{k}=0,$ $t_{eye}=UI/2$. In other words, it is assumed that at $t=0$, the waveform is at the center of one unit interval, and is therefore at the center of the eye. If this is not the case, and you need the eye to be at the center, you would modify the delay value in the [Eye Probe](23-Built-in-Devices-Parts.md#device:Eye-Probe) or [Differential Eye Probe](23-Built-in-Devices-Parts.md#device:Differential-Eye-Probe) element, and re-run the simulation. Oftentimes, one just wants to get a general look, and when the [Number of UI](22-Eye-Diagram-Properties.md#sub:Number-of-UI) is specified as its default value of 3, you will see at at least one of the eyes in its entirety.

The eye is generated starting with an empty array that is the [Number of Rows](22-Eye-Diagram-Properties.md#sub:Number-of-Rows) in height, and the [Number of Columns](22-Eye-Diagram-Properties.md#sub:Number-of-Columns) in width. In order to count the hits in each column of pixels, the waveform is upsampled such that every waveform point is a column of the array. Because this upsampling is expensive in both processing time and memory, it is useful for the upsample factor to not be too large (hence the default [Number of Columns](22-Eye-Diagram-Properties.md#sub:Number-of-Columns) = 200). It is also useful for the upsample factor to be a nice ratio of the original sample rate of the waveform.

For a given sample rate, $Fs$, number of columns, $C$, and baudrate, $R$, the upsample factor $U$ is given by: $$U=\frac{R\cdot C}{Fs}\mbox{.}$$

For example, if the incoming waveform is at $20\:GS/s$ sample rate, at a baud rate of $5\:GBaud$, and there are 200 columns in the eye diagram, the upsample factor is $5\cdot200/20=50$. What you definitely want to avoid is for the upsample factor to be a ratio of numbers, especially with a large number in the numerator.

Once the waveform is upsampled, a number of points $\le C$, are trimmed such that the first point of the waveform is in column 0.

Then, the maximum and minimum voltage associated with each row is calculated, using [Y Axis](22-Eye-Diagram-Properties.md#sub:Y-Axis) mode, in conjunction possibly with [Minimum Y](22-Eye-Diagram-Properties.md#sub:Minimum-Y) and [Maximum Y](22-Eye-Diagram-Properties.md#sub:Maximum-Y). This allows for the calculation of the row, with respect to the voltage. For each waveform point (a column), the row is calculated, and a one is added to the array. Usually, it is spread over a row and the correct fractional amounts are allocated.

At this point, the ISI only bitmap array is complete. If the [Eye Mode](22-Eye-Diagram-Properties.md#sub:Eye-Mode) is Jitter & Noise, some extra steps are now performed. In this case, a kernel is created. This is an array that contains a Gaussian vertically that encompasses the [Noise](22-Eye-Diagram-Properties.md#sub:Noise), and a Gaussian horizontally that encompasses the [Random Jitter](22-Eye-Diagram-Properties.md#sub:Random-Jitter) jitter convolved with a dual-Dirac delta function representing the [Deterministic Jitter](22-Eye-Diagram-Properties.md#sub:Deterministic-Jitter). This array is constructed so that it sums to unity. This kernel is convolved with the bitmap array, serving to smear out the eye. To handle pathological cases, the kernel is limited to the [Max Kernel Pixels](22-Eye-Diagram-Properties.md#sub:Max-Kernel-Pixels).

For Jitter & Noise [Eye Mode](22-Eye-Diagram-Properties.md#sub:Eye-Mode)s, a further option exists to show the eye logarithmically. If [Log Intensity](22-Eye-Diagram-Properties.md#sub:Log-Intensity) is True, the eye diagram is re-scaled such that each pixel contains a probability of hitting that pixel, and the eye diagram is saturated in a log-linear fashion with a zero indicating that the probability is at or below a number indicated by the [Min Exponent](22-Eye-Diagram-Properties.md#sub:Min-Exponent), and one indicating that the probability is at or above a number indicated by the [Max Exponent](22-Eye-Diagram-Properties.md#sub:Max-Exponent).

At this point, the processing joins where it would resume following the ISI Only [Eye Mode](22-Eye-Diagram-Properties.md#sub:Eye-Mode) processing if Jitter & Noise were not specified.

The bitmap is now duplicated according the [Number of UI](22-Eye-Diagram-Properties.md#sub:Number-of-UI) specified. If Jitter & Noise were not specified for the [Eye Mode](22-Eye-Diagram-Properties.md#sub:Eye-Mode) and [Log Intensity](22-Eye-Diagram-Properties.md#sub:Log-Intensity) was not specified, the eye is then re-saturated using a spline such that the maximum intensity is achieved at a value at or above the [Saturation](22-Eye-Diagram-Properties.md#sub:Saturation).

The eye is then inverted or not, depending on the setting of [Invert Plot](22-Eye-Diagram-Properties.md#sub:Invert-Plot), and colorized according to the specified [Bits per Symbol](22-Eye-Diagram-Properties.md#sub:Eye-Diagram-Bits-per-Symbol).

Finally, the image is scaled according to the [Scale X](22-Eye-Diagram-Properties.md#sub:Scale-X) and [Scale Y](22-Eye-Diagram-Properties.md#sub:Scale-Y) settings. Further re-scaling is possible by simply resizing the final canvas.
